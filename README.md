# 千川直播周报 Codex Skill

一个面向抖音电商经营者的 Codex Skill：把电商罗盘与巨量千川的周度数据整理成可回查、可验收的直播经营周报。

## 1. 这个 Skill 面向谁

- 使用 Codex 桌面客户端工作的抖音电商负责人、直播运营和数据分析人员。
- 采用“千川付费素材/直播间推广引流，直播间承接成交”模式的团队。
- 希望每周稳定复用同一套字段、公式、数据质量检查和报告结构的用户。
- 能从自己的后台导出官方数据，或愿意配合 Codex 完成浏览器登录与权限准备的用户。

这个 Skill 只面向 Codex 安装和使用，不承诺兼容其他 Agent、IDE 或聊天产品。

## 2. 它解决什么问题

它把容易反复返工的直播周报流程固化下来：

- 校验账号、周期、字段结构和退款成熟度，避免混账号、混周期。
- 保留罗盘原始数据，补充逐场直播详情和同周期千川结果。
- 计算直播成交漏斗、自然/项目计算付费观看结构、自然流撬动系数、千次观看支付等指标，并兼容乘方页面的“综合营销ROI”字段。
- 生成并回读验收四张工作表：`场次核心明细`、`周报汇总`、`数据底表`、`数据字典`。
- 区分“完整交付”“部分数据草稿”和“被权限阻塞”，不把缺数据结果包装成完整周报。

它解决的是平台经营效率诊断，不是财务利润核算。没有商品、履约、达人佣金等成本时，不能据此判断真实利润。

## 3. 两种数据获取模式

### 文件模式

用户从官方后台人工取得文件，Codex负责校验、清洗、匹配、计算、生成和验收周报。

适合：

- 不希望开放浏览器控制。
- 后台存在验证码、风控或复杂权限。
- 团队已经有稳定导出流程。

### 全自动模式

在用户完成客户端、Chrome插件、后台登录和网站权限准备后，由 Codex 通过已登录的 Chrome 完成官方导出、逐场补数和同周期数据核验。

全自动不代表绕过登录。验证码、二维码、滑块或风控出现时，Codex必须停止，等待用户本人处理。

## 4. 每种模式的前提条件

### 文件模式需要准备什么

基础报告至少需要：

- 电商罗盘“直播明细”官方导出：单一账号、完整周、每场一行。

完整报告还需要：

- 逐场直播详情补数：可使用 Skill 自带 CSV 模板，至少包含开始时间、`live_room_id`、自然流量观看人数和抓取时间。
- 巨量千川同账号、同完整周期经营结果。

如果还要诊断计划和素材，需要追加千川计划/素材导出。Skill 安装后会先确认报告完整度，再给出对应的数据清单，不会要求用户准备无关文件。

### 全自动模式需要准备什么

安装 Skill 前请确认：

- 可正常使用的 Codex桌面客户端。
- 已安装、启用并连接官方 Chrome插件。
- Codex 和插件使用同一个Chrome用户配置。
- 已在该 Chrome 中登录 `compass.jinritemai.com`。
- 已在该 Chrome 中登录 `qianchuan.jinritemai.com`。
- 当前账号有权查看目标直播间和千川数据。
- 已允许两个后台域名及任务所需的下载权限。

Codex 会先抓取 2—3 场做小样本验证，通过后才跑完整周。页面结构变化或权限不足时会给出精确阻塞原因。

## 5. Excel 与飞书两种交付方式

两种数据获取模式都可以选择 Excel 或飞书表格。

### Excel

- 不需要安装 `lark-cli`。
- Codex 生成本地 `.xlsx` 后会回读校验工作表、场次数、原始值、ID文本和公式错误。
- 回读通过才算完成。

### 飞书表格

- 需要安装并配置飞书官方 `lark-cli`。
- 需要用户完成飞书自建应用配置、最小权限授权，并选择一个用户 profile。
- 默认使用 `--as user`，写入后必须用同一用户身份回读。
- 本地 Excel 会保留为已验收备份，但不能代替用户请求的飞书最终交付。

若飞书安装、权限、写入或回读最终无法完成，Skill不得自动回退，只能询问：

> 飞书表格当前无法完成，是否确认将本次最终交付回退为Excel文件？

只有用户明确确认后，本地 Excel 才能成为本次最终交付。

## 6. 使用边界与不适合情况

- 一次只处理一个主播/直播间账号的一周数据。
- 只能访问用户本来就有权查看的后台和资源。
- 不读取或要求用户提供密码、Cookie、token、验证码或浏览器会话。
- 不绕过平台登录、安全校验、风控或下载限制。
- 不把“总观看减自然观看”称为平台官方付费观看；报告中标记为项目计算口径。
- 页面字段变化、账号权限不足或周期数据不完整时，只输出已验证结果和补数清单。
- 不适合需要跨店铺归因、财务利润核算、实时投放自动调价或无人值守绕过风控的场景。

## 7. 安装

在 Codex 中粘贴下面这句话：

```text
请使用 skill-installer 从这个GitHub地址安装千川直播周报Skill：
https://github.com/639happy/qianchuan-live-weekly-report-skill/tree/main/qianchuan-live-weekly-report
```

安装完成后，重新打开一个 Codex 任务，直接说：

```text
请使用千川直播周报 Skill，帮我生成上周的直播经营周报。
```

## 8. 第一次使用

Skill 会一次只问一个关键问题，顺序固定：

1. 报告完整度：基础、完整或付费诊断扩展。
2. 数据获取模式：文件模式或全自动模式。
3. 最终交付：Excel 或飞书表格。
4. 账号、周期、时区、退款成熟度和场次分组。
5. 本周是否发生主播、商品、价格、优惠、货盘、时长或投放方式变化。

确认后，Codex 会展示运行确认卡，再开始读取数据。配置由 Codex 写入用户自己的工作区，不要求非技术用户手写 JSON。

## 9. 数据与隐私

- 仓库只包含合成测试数据，不包含真实账号、店铺、直播间、飞书资产或经营数据。
- 下载文件、报告、浏览器运行记录和用户配置只能保存在用户工作区，不写入 Skill 安装目录。
- 仓库自带发布前敏感信息扫描器，检查本地用户路径、长数字ID、飞书资源链接、带查询参数的后台URL、凭证赋值和常见导出/媒体文件。
- 提交 Issue 时不要上传真实导出、后台截图、Cookie、token、账号ID、后台URL、飞书链接或经营数据。
